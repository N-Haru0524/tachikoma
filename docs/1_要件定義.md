# タチコマ型 同居人ロボット ― 要件定義

体長20〜30cmの小型移動ロボット。長い設計対話と Phase 1 シミュレーション（MuJoCo）を経て確定した、コンセプトから移動・脚機構・モーター選定・検証方針までの土台。本ドキュメントは実装（Claude Code に委譲）の入力仕様を兼ねる。

---

## 1. コンセプト（北極星）

**「そばにいて和む同居人」**。これが最上位の目的。

- 和み方は生物模倣ではなく、**「機械であることを隠さない」メカ愛**。生き物のフリではなく、機械が機械のまま動くことの愛おしさを狙う。剛体の機械的な動作（カチッと動く）を積極的に肯定する。
- 参照系譜：WALL-E、R2-D2、AT-ST、Droideka、そして着地点の**タチコマ**（多脚＋車輪、意志のある動き）。
- 当初の実用背景（スマートホーム家電のセンシング・巡回）は上位目的に従属。安定した移動プラットフォームとして自然に両立する。

## 2. 設計原則

- **こけないことが最優先**。移動の安定は車輪が担保し、脚に歩行の責任を負わせない。
- **アクチュエータ最小化は目的ではない**。タチコマらしさ（動きの表現力）を優先し、必要な軸は惜しまない。
- **まずシミュレーション（MuJoCo）で完結**させ、段階的に検証してから実機へ。

## 3. 移動系 ― swerve 的な「向けて走る」構成

- 各脚に**股ヨー関節（操舵）**＋脚先に**普通ホイール（駆動）**。実質 swerve drive。
- **4本脚すべて能動**。全脚が意志を持って向きを変え走る＝タチコマらしさ。
- **非ホロノミック**を意図的に選択。メカナムのような無機質な横滑り平行移動ではなく、「脚と車体を向けてから走る」方向性のある動きこそがタチコマの生き物っぽさ・愛嬌の源泉。効率ではなく**表現**としての選択。
- **普通ホイール採用の理由**：向いた方向にしっかりグリップ＝方向性が明確、自己位置推定（オドメトリ）が正確、「キュッと向きを変える」機械的な質感がメカ愛に合う。
- **θ回転（その場回転）**：各輪を車体中心まわりの円の接線方向へ操舵し、全輪同方向に駆動すれば実現。定常回転中は引きずらない。スクラブが出るのは操舵角を変える過渡のみ。

## 4. 脚系 ― 股2軸の棒脚（テンドンは不採用）

設計対話の中でテンドン駆動を検討したが、最終的に**不採用**。理由は、(1) 剛体の機械的な動作の方が「機械であることを隠さない」メカ愛に合う、(2) テンドンのワイヤ地獄（テンション調整・摩擦・経年の伸び）を回避でき、3Dプリンタ＋サーボで確実に作れる、(3) コンプライアンス（衝撃吸収）は足首の受動サスペンションで別途担保できるため。

- 脚は**膝を持たない「棒一本」**。付け根の**股2軸（ヨー＋ピッチ）**で振る構成。
- **股ヨー（能動）**：脚を水平に振り、車輪の向きを作る。操舵の主役。
- **股ピッチ（能動）**：脚を前後・上下に振る。段差越え（脚を振り出して段に置く）、車高・姿勢の調整、伸び・お辞儀などの仕草。**車体重量を支える主軸**でもある。
- **足首ショックアブソーバー（受動）**：接地衝撃の吸収、4輪接地時の凹凸追従。コンプライアンスはここで担保。
- モーターが両方とも付け根に集約されるため脚先が軽く、振り回しやすい（運動性能に有利）。

### この構成の割り切り（既知の制約）

- 膝が無いため脚長は固定。車高調整は股ピッチで脚を斜めにする形になり、車高と接地点が連動する（その場で縮むことはできない）。足首サスと、主用途が3cm段差・平地巡回であることから実用上は許容範囲。
- 段差越えで脚を振り出すと足先が前に出て接地点が動くため、4脚の接地バランスに配慮が要る。ただし移動の安定はホイールが担保するため静的転倒リスクは低い。

## 5. 自由度・アクチュエータ構成

**脚1本 = 股ヨー（能動）＋ 股ピッチ（能動）＋ 脚先ホイール（能動）＋ 足首サス（受動）**

これを **×4本**。

- 能動：**12軸**（股ヨー4 ＋ 股ピッチ4 ＋ ホイール4）
- 受動：足首サス4

**表現系（和みの主戦場、詳細は次フェーズ）**：頭／センサ部のパン・チルト、レンズ（目）の動き、音・仕草。

## 6. 物理パラメータ

| 項目 | 値 | 備考 |
|------|-----|------|
| 体長 | 20〜30cm | 脚を除く車体 |
| 目標総重量（全備重量） | **1.3kg 前後**（上限1.5kg） | Raspberry Pi＋カメラ（画像処理）込みで積算した現実値。脚・サーボ・電池・電子部品すべて込み |
| 想定段差 | 3cm | 膝なしのため、股ピッチで脚を振り出し車輪を段上に置く step 動作で越える |
| ホイール径 | **3cm 固定**（半径1.5cm） | 段差と同高のため転がり越えは原理的に不可＝脚で越える仕様と整合。車輪は平地推進に専念 |
| 段差越えの手順 | **1脚ずつ**（前2脚同時は不採用） | 常に3脚支持で安定。ただし pull-up 時は1脚に荷重が集中する |
| 駆動電圧 | 7.4V（2セル）想定 | サーボのストールトルク確保のため |

**重量の定義**：モーター選定に使う重量は脚を含む全備重量。股ピッチが支えるのは「車体を上から押す荷重の全部」であるため、総重量が計算入力となる。サーボが重量・トルクの両方を握る（大トルク→重い→もっとトルク）ため、フレーム軽量化で総重量を抑える努力が選定を楽にする。

## 7. Phase 1 シミュレーション実測結果（MuJoCo・脚1本 rig）

脚1本モデル（股ヨー＋股ピッチ＋ホイール＋足首サス）で、姿勢保持と段差 pull-up の股ピッチトルクを実測。

**測定内容の切り分け**：単脚は自分自身を持ち上げられない（振り出し局面では足が唯一の支持点になり車体が落ちる）。「空中で脚を振り出して段上に置く」局面は多脚協調＝Phase 2 の領分。本 rig では**「車輪を段上に置いた状態」を初期姿勢**とし、要件が主眼に置く「荷重を移して車体を引き上げる（pull-up）」トルクを測定した。

| 荷重条件 | 保持ピーク | 段差 pull-up ピーク | サイジング(×2) |
|----------|-----------|---------------------|----------------|
| 1.5kg（安全側・全荷重が1脚） | 1.49 N·m | 2.03 N·m | ~4.1 N·m |
| 0.375kg（4脚静的分担） | 0.42 N·m | 0.73 N·m | ~1.5 N·m |

- 段差越えの律速は **pull-up**（保持より重い）。直感どおり。
- pull-up ピークは「引き上げ開始＝最大レバー時」に発生。車体高 0.142→0.176（+33mm＝3cm段を登り切る）を確認。
- トルクは荷重にほぼ線形。**1脚ずつ手順では pull-up 時に1脚へ荷重が集中する**ため、選定は集中荷重側で見る。

**実装上の記録（Phase 1 で解消済み）**：脚ロッドの自己衝突→接地をホイールのみに限定（contype/conaffinity）。小径ホイールの接触が柔らかすぎ15mm埋没→solref/solimp を締め3mmに。pitch 符号が座標定義と逆→前方リーチを負 pitch に修正。

## 8. モーター選定（確定）

コンプライアンスを足首サス（受動・機械）で担保するため、能動関節は**位置/速度制御で足り、電流制御やバックドライバブルな高級モーターは不要**。

段差越えを **1脚ずつ**（前2脚同時は不採用）とした結果、pull-up 時に荷重が1脚へ集中する。総重量1.3kg前提で pull-up ピーク ≈ 1.6〜1.7 N·m、安全率2で ~3.2〜3.4 N·m。これは STS3215 のストール（1.5〜3 N·m）を超え、STS3250 の射程（3〜4 N·m）に収まる。

**トルクが要るのは股ピッチのみ**という非対称を活かし、混載で最適化する：

| 系統 | 本数 | 選定 | 根拠 |
|------|------|------|------|
| **股ピッチ** | ×4 | **Feetech STS3250 級（3〜4 N·m）** | pull-up と車体支持の主軸。最大トルクの律速 |
| **股ヨー** | ×4 | **Feetech STS3215 級（1.5〜3 N·m）** | 操舵。車体を持ち上げないため軽負荷 |
| **ホイール** | ×4 | ギアードDC＋エンコーダ or 連続回転サーボ | 連続回転・速度制御。トルクより回転数と効率 |

- STS3215 と STS3250 は Feetech 同系でバス互換・寸法が近く、**混載しても制御・配線は一系統**（TTL/RS485 デイジーチェーン）。
- **7.4V 駆動**でストールトルクを確保する前提。
- 股ピッチを 3250 にすると +100g 弱（総重量 ~1.3kg）。再 sim でも pull-up ~1.7 N·m と 3250 射程内に収まり、重量↔トルクの循環は収束する。

## 9. 検証・実装フェーズ

- **Phase 1（完了）**：MuJoCo 脚1本 rig。姿勢保持・段差 pull-up の股ピッチトルクを実測（§7）。→ モーター選定確定（§8）。
- **Phase 2**：4脚＋車体の全体モデル。**1脚ずつの段差越えシーケンス**（振り出し→段上に置く→荷重移動→pull-up を多脚協調で通す）、非ホロノミック移動（swerve の向けて走る／θ回転）を統合。ここで越え手順が確定したら要求トルクを再サイジング。ROS2 の planning と接続。
- **Phase 3**：実機化。3Dプリンタ＋スマートサーボ（股ピッチ STS3250／股ヨー STS3215）。実測トルクに基づく最終確認、フレーム軽量化。

## 10. 次に詰める項目（保留事項）

- Phase 2 の段差越えシーケンス（1脚ずつの振り出し局面を多脚協調で通す）と、それに基づく要求トルクの再確認。
- ホイール駆動モーターの具体選定（径3cm固定での必要回転数・トルク）。
- 表現系（目・音・首）の具体設計。
- swerve 制御（各輪の操舵角＋駆動速度の協調）と、非ホロノミックな軌道生成の方針。
- バッテリー容量・電源系（Raspi＋画像処理＋サーボ12軸のピーク電流）。

### 前提（実装環境・スキル）

CAD／3Dプリンタ／サーボ制御（PID・現代制御）／ROS2 planning／MuJoCo・Isaac 経験あり。組込みは Arduino を少々。実装は「まずシミュレーションで挙動を確定 → 実機で詰める」方針。シミュレーションは Claude Code（Remote Control 経由でローカルの MuJoCo 環境を使用）に委譲する。
